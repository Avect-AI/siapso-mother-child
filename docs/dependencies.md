# Dependencies: open alerts and revisit dates

Dependabot version updates wait 14 days after a release (`cooldown` in `.github/dependabot.yml`, the same as `minimumReleaseAge` in `pnpm-workspace.yaml`). A fixed version is therefore not proposed, and cannot be installed, until it is 14 days old. Four Dependabot alerts were open on 2026-11-04. All four are build-time only, never shipped in the app or run on a phone: serialize-javascript, deepmerge and minimatch 5 come from `workbox-build` (pulled in by `vite-plugin-pwa`) to generate the service worker; minimatch 10 and glob come from development tooling (ESLint and the build).

| Alert | Package                      | Fixed version | Severity | Eligible (14 days old) | Revisit    |
| ----- | ---------------------------- | ------------- | -------- | ---------------------- | ---------- |
| 2     | serialize-javascript (7.1.2) | 7.1.3         | low      | 2026-11-05             | 2026-11-05 |
| 4     | glob (11.1.0)                | 14.0.2        | medium   | 2026-11-10             | 2026-11-10 |
| 1     | minimatch (10.2.6 and 5.1.9) | 11.0.1        | medium   | 2026-11-10             | 2026-11-10 |
| 3     | deepmerge                    | none yet      | low      | no fixed version       | 2026-11-17 |

## Plan

1. On each revisit date, check whether Dependabot opened a pull request for the package (`gh pr list --label dependencies`), and merge it through the usual gate when CI is green.
2. If Dependabot cannot update because the range declared by `workbox-build` excludes the fixed version (glob and minimatch are several majors ahead of the range `workbox-build` declares), add a pnpm override in `pnpm-workspace.yaml`, for example `overrides: { 'serialize-javascript@<7.1.3': '7.1.3' }`, then run `pnpm install`, `pnpm build` and the app tests. The service worker must still be generated and `pnpm budget:app` must still pass. Remove the override as soon as `workbox-build` ships a range that includes the fixed version.
3. If an override breaks the build (a major API change in glob or minimatch), do not force it: record the reason here, keep the alert open with its dismissal reason ("not used at runtime, build-time only"), and revisit when `workbox-build` or `vite-plugin-pwa` is updated.
4. deepmerge has no fixed version: check the advisory on the revisit date and again whenever `workbox-build` changes. Dismiss it as "not used at runtime" if nothing is fixed by then, with a note in this file.

Update this table when an alert is closed.

## Speech conversion tooling (Python)

`speech/convert/` runs on a developer machine only, never in the app or on a phone. Its hashed lock (`requirements.txt`, generated by `lock.py` from `requirements.in`) was moved on 2026-11-05 to the lowest patched versions published on or before 2026-10-22 (14 days before). `lock.py check` passes on Windows x86_64, Linux x86_64 and aarch64, and macOS arm64, with Python 3.10 to 3.12.

| ---------------------- | -------- | ------ | -------------------------------- | -------------------------------------------------------------- |
| 43 (high), 14 (low)    | torch    | 2.8.0  | 2.10.0 (2026-02-10)              | closed                                                         |
| 16, 19, 39, 40, 41, 42 | onnx     | 1.19.1 | 1.22.0 (2026-06-15)              | closed                                                         |
| 22 to 38 (filelock)    | filelock | 4.1.0  | 4.2.1 (2026-10-17), Python 3.11+ | closed on Python 3.11 and 3.12; open on 3.10 (exception below) |

Exceptions and limits:

- filelock 4.2.1 requires Python 3.11 and no fixed version supports Python 3.10, so `requirements.in` keeps 4.1.0 for Python below 3.11. Use Python 3.11 or 3.12 for the conversion. The alerts concern locks shared between local users on one machine, which the conversion does not do; Python 3.10 reached end of life in October 2026, so support for it can be dropped at the next change of the set.
- torch alert 18 (low, memory corruption in `torch.jit.script`, fixed in 2.13.0, published 2026-07-08) is still open: the conversion does not call `torch.jit.script` on untrusted input, and 2.13 was not asked for here. Revisit when `transformers` and `optimum-onnx` are moved.
- transformers (alerts 12, 15, 17, 20, 21) is not moved: the fixes are in 5.x, which `optimum-onnx` 0.1.0 does not accept (it needs transformers below 4.58). The conversion only loads two pinned public checkpoints and never custom code.
- The lock was verified with Python 3.10 only on the machine used (see the pull request for the conversion and word error rate check).

## Speech training tooling (Python)

`speech/train/` (the fine-tuning script `finetune.py`) is meant for a GPU training machine only, is never shipped in the app or run on a phone, and has never been run for training. Its hashed lock (`requirements.txt`, generated by `speech/convert/lock.py` from `requirements.in`) was moved on 2026-11-05 to the lowest fixed versions published on or before 2026-10-22 (14 days before); accelerate, which has no fixed version, moved to the latest eligible one. `lock.py check --dir speech/train` passes on Linux x86_64 with Python 3.11 and 3.12. This replaces Dependabot pull request 41 (datasets alone, outside `lock.py` and its release-age check).

| Alerts                         | Package      | Before   | Now (published)       | Status                                               |
| ------------------------------ | ------------ | -------- | --------------------- | ---------------------------------------------------- |

Other changes the new versions need: huggingface-hub 0.36.2 to 1.33.0 (transformers 5.10 needs at least 1.5 and, like datasets 5.0.1, below 2.0; 1.33.0 is the newest 1.x published before the cutoff), new transitive pins (httpx, typer and their dependencies), and the CUDA 13 libraries of torch 2.13 in place of CUDA 12.8: the training machine needs an NVIDIA driver for CUDA 13.0 (R580 or newer). fsspec 2026.6.0 is also the highest version datasets 5.0.1 accepts. datasets 5 encodes and decodes audio only through torchcodec, which needs FFmpeg libraries outside the hashed lock, so `finetune.py` now decodes audio with `soundfile` (pinned) and lists local folders itself, refusing any file outside the folder.

Alerts with no upstream fix:

- 50, transformers, GHSA-x9r9-c232-4q39: `load_custom_generate` writes a repository's `custom_generate/generate.py` to the cache before the trust check. The advisory lists versions up to 5.8.1 and no fixed version, and 5.10.1 still fetches the file before `resolve_trust_remote_code` (read in the installed package on 2026-11-05). Dependabot may close the alert because 5.10.1 is outside the listed range; we treat it as open until the advisory names a fixed version. In 5.10.1 that function runs only when a model is loaded with `trust_remote_code=True` or when `generate` gets a `custom_generate` argument; `finetune.py` does neither.
- 49, accelerate, GHSA-4j2p-28q2-5m79: `load_checkpoint_in_model` and `load_checkpoint_and_dispatch` follow the `weight_map` entries of a sharded checkpoint index without checking that they stay in the checkpoint folder. The advisory lists versions up to 1.14.0 and no fixed version; the two proposed fixes (accelerate pull requests 4070 and 4138) were closed without being merged, and 1.15.0 still joins the entries unchecked. Same note on Dependabot. Neither `finetune.py` nor the transformers `Trainer` calls these two functions (checked in the installed packages).

Mitigation (tested by `speech/train/test_finetune.py`):

- Only pinned trusted repositories: the base model must be `openai/whisper-tiny` or `openai/whisper-base` and a Hub dataset `google/fleurs`, each at the full commit pinned in `finetune.py` (a branch, tag, pull request ref or short commit is refused, and so is a local folder named like the repository); any other repository is refused before a download, with `--check-only` too.
- No remote code: every `from_pretrained` passes `trust_remote_code=False`, no call passes `custom_generate`, and datasets 5 cannot run dataset scripts.
- Weights are loaded only from the pinned base and from the run's own output folder: the Trainer reloads the best checkpoint of the run at the end of training. `finetune.py` then saves the final model there and does not load it back.
- The tooling runs on a training machine only, never in the app or on a phone.

Revisit on 2026-11-19, and before the first training run: check the advisories of alerts 49 and 50 for a fixed version and move to it through `lock.py` once it is 14 days old; if Dependabot closes them on the version range alone, note it here and keep the mitigation. Before training, run `lock.py check --dir speech/train` and `test_finetune.py` with the lock installed on the training machine. The lock was installed and tested on Windows x86_64 with Python 3.12 only (CPU build of torch, without the Linux-only CUDA pins); the Linux CUDA install has not been tried, for lack of a GPU machine.
