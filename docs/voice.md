# Voice input

Say a medicine or remedy name in Wolof or French, with no network, and get candidates to confirm. The speech model only proposes text: the resolver proposes candidates, the user confirms one, and the deterministic engine alone decides the level. Keyboard search works without any of this.

## Packs

The model is an optional voice pack, downloaded on request (on wifi at the health post, for example), stored in the Cache API and read from there with no network. One pack per language:

| Pack id                  | Source (revision)                                                          | Licence | Language | Served size (model + ONNX Runtime + notices)     |
| ------------------------ | -------------------------------------------------------------------------- | ------- | -------- | ------------------------------------------------ |
| `whisper-small-wolof-q8` | `M9and2M/whisper-small-wolof` (`8cc20b3c6e77ecb490210103d3b4fd0b85c3d1d8`) | MIT     | Wolof    | 325,959,007 bytes, 326.0 MB (298.7 MB + 27.3 MB) |
| `whisper-base-fr-q8`     | `openai/whisper-base` (`e37978b90ca9030d5170a5c07aadb050351a65bb`)         | MIT     | French   | 137,502,694 bytes, 137.5 MB (110.2 MB + 27.3 MB) |

Licence chain:

- Models: OpenAI Whisper small and base (OpenAI states in the README of `github.com/openai/whisper` that the code and model weights are released under the MIT License; the Hugging Face cards of `openai/whisper-small` and `openai/whisper-base` declare apache-2.0, also permissive), and the fine-tune `M9and2M/whisper-small-wolof` (MIT, declared on its card, checked at the revision above).
- Training data of the fine-tune: its dataset `M9and2M/Wolof_ASR_dataset` lists ALFFA, WAXAL, FLEURS (`google/fleurs`, `wo_sn`) and a Wolof TTS corpus on Zenodo; the dataset card states no licence for them. Each source was checked on its own page (`speech/LICENSES.md`): FLEURS CC-BY-4.0 and the Zenodo Wolof TTS corpus CC-BY-4.0 are verified, WAXAL is CC-BY-SA-4.0 (share-alike effect on the weights unresolved), ALFFA Wolof audio is unverified (no data licence stated). The model card, ready for Hugging Face, is `speech/MODEL_CARD.md`. Meta MMS and non-commercial data are not used by SIAPSO.
- Runtime: Transformers.js 4.3.1 (Apache-2.0, Copyright Hugging Face), with `@huggingface/tokenizers` 0.2.0 (Apache-2.0) and `@huggingface/jinja` 0.5.10 (MIT), bundled in the speech worker; ONNX Runtime Web `1.31.0-dev.20260914-8d85527a0` (MIT, Copyright Microsoft Corporation). The worker source carries a preserved licence comment (`/*! ... */`, kept in the built chunk) that points to the texts, and each pack ships them: `licenses/` (Transformers.js, tokenizers and jinja licence files, the MIT text of Whisper, and ONNX Runtime's `LICENSE` and `ThirdPartyNotices.txt`, the notices of the third-party code its WebAssembly links) and `NOTICE.md`. The two ONNX Runtime texts come from `microsoft/onnxruntime` at `8d85527a010e294a26b274749f74294b2a32cec5`, the commit the installed `onnxruntime-web` names in its `__commit.txt`; `pnpm voice:install-local` checks each by size and SHA-256 (`speech/LICENSES.md`) and refuses an `onnxruntime-web` built from another commit.

Each pack holds `onnx/encoder_model_quantized.onnx`, `onnx/decoder_model_merged_quantized.onnx` (8-bit weights), the Whisper configuration and tokenizer files, the ONNX Runtime Web files (`runtime/<version>/`), the licence texts (`licenses/`, among them `licenses/onnxruntime-web-LICENSE.txt` and `licenses/onnxruntime-ThirdPartyNotices.txt`, and `NOTICE.md`) and `voice-pack.json` (files with size and sha256, licence, languages, decoder prompt, source revision, and the ONNX Runtime Web version in `runtime`). The pack folder is served from the app origin, by default `voice/<pack id>/` next to the app (`VOICE_PACKS` in `@siapso/speech`). How a pack is built: `speech/convert/README.md`.

## The French decision

Measured with `speech/convert/quick_check.py` on the first 20 sentences of the FLEURS test splits (CC BY 4.0, revision `70bb2e84b976b7e960aa89f1c648e09c59f894dd`), 8-bit graphs, decoded as in the browser (greedy, the same prompt and suppressed tokens, at most 96 new tokens); word error rate after lowercasing and removing punctuation, accents kept:

| Pack                     | Language (FLEURS, words) | Prompt `<\|startoftranscript\|>` alone | Prompt `<\|startoftranscript\|><\|fr\|><\|transcribe\|><\|notimestamps\|>` |
| ------------------------ | ------------------------ | -------------------------------------- | -------------------------------------------------------------------------- |
| `whisper-small-wolof-q8` | Wolof (`wo_sn`, 441)     | **55.6 %**                             | 72.1 %                                                                     |
| `whisper-small-wolof-q8` | French (`fr_fr`, 534)    | 93.3 %                                 | 69.3 %                                                                     |
| `whisper-base-fr-q8`     | French (`fr_fr`, 534)    | 125.8 %                                | **30.0 %**                                                                 |

The first measure decoded up to 448 tokens: the same 55.6 %, 69.5 % and 30.0 % in the cells that matter; the other cells were higher (129.2 %, 112.9 %, 257.3 %) because a wrong prompt makes the model repeat itself, and the 96-token limit cuts those loops short.

- The Wolof fine-tune was trained with `<|startoftranscript|>` alone: right after it, the model writes Wolof text, with no language, task or timestamp token, even for French audio. Transformers.js would otherwise add `<|en|><|transcribe|><|notimestamps|>` (it has no language detection), so the pack records its decoder prompt and the worker passes it.
- French through the Wolof fine-tune is above the 40 percent limit of the plan (69.3 %, with Wolof-like spellings of French words). Decision: French uses its own pack, built the same way from the multilingual Whisper base model (30.0 %), and the language is a choice: each pack declares `languages: ['wo']` or `languages: ['fr']`. The voice screen (SCRUM-31) offers the language and says which model it uses.
- The Wolof figure may be optimistic: the fine-tune's training dataset (`M9and2M/Wolof_ASR_dataset`) lists `google/fleurs` `wo_sn` among its sources without saying which splits, so some of these FLEURS test sentences may have been seen in training. The fine-tune's card gives a word error rate of 0.17 on its own test set. Only consented recordings that were never used for training measure the model fairly (SCRUM-32).
- Part of the Wolof error rate is spelling: Wolof spelling varies (`nuy` and `ñuy`, `diwaan` and `diiwaan`, `gëna` and `gën`), and each variant counts as an error. Name accuracy after the resolver is what matters for SIAPSO; it is measured on consented recordings in SCRUM-32.
- Quantising the token embedding (Gather) to int8 as well as MatMul saves 120 MB on the Wolof pack. With the Wolof prompt, the only one the Wolof pack uses, the loss is not measurable: 55.6 % against 56.7 % with MatMul only (decoding up to 448 tokens). That holds for the Wolof prompt only: with the French prompt the two graphs swung widely, both ways (Wolof 129.2 % against 62.4 %, French 69.5 % against 103.2 %), because of repetition loops. The MatMul-only graphs were not kept, so this comparison was not repeated with the 96-token limit.

## Runtime

- `@siapso/speech` runs Transformers.js 4.3.1 in a dedicated Web Worker (`createSpeechClient`). The worker sets `allowRemoteModels = false`, `allowLocalModels = true`, `localModelPath` to the folder of the pack, the browser cache on with `cacheKey` set to the cache that `installVoicePack` fills (`transformers-cache`), `dtype: 'q8'`, and `device: 'webgpu'` when `navigator.gpu` gives an adapter, else `'wasm'` (and falls back to WebAssembly if WebGPU fails to start).
- Nothing is downloaded without the user's consent. The client first checks that every file of the pack is installed (`VoicePackError` `unavailable` otherwise, and the worker is not asked to load). The worker's `fetch` never uses the network: it answers files listed by the pack from the Cache API only, a file that is not installed answers 404 (a load error, never a download), and any other URL is refused, so it never reaches the Hugging Face hub or a CDN (tested in `speech/test/runtime-config.test.ts`; the bench checks in a browser that a load before installation fails and fetches no model file, and that nothing at all is requested once offline).
- ONNX Runtime Web loads its binaries (`runtime/<version>/ort-wasm-simd-threaded.asyncify.{mjs,wasm}`) from the pack, not from the jsDelivr CDN that Transformers.js uses by default.
- The runtime files must be the build whose JavaScript the speech worker bundles: `ORT_WEB_VERSION` in `speech/src/voice-pack.ts` (`1.31.0-dev.20260914-8d85527a0`, a dev build that Transformers.js 4.3.1 pins). They live under `runtime/<version>/`, the manifest says the version (`runtime: { "onnxruntime-web": ... }`), and the stored copy keeps it. A pack built for another version is refused (`invalid`), and one already installed then reads as not installed: the voice screen shows what is on the phone and offers to go on, and the installation downloads only the runtime files at their new path (the rest is kept by path) and drops the old ones. `speech/test/ort-version.test.ts` fails in CI when the bundled `onnxruntime-web` is not `ORT_WEB_VERSION`, and `pnpm voice:install-local` refuses another installed version.
- Errors reach the page as `VoicePackError` with a reason for the voice screen: `unavailable` (not installed, or the server does not give it: no network, a 404 for the manifest or a file, the app page instead of the manifest), `invalid` (a manifest that is not a pack, or a file received whole but of another size than the manifest says: damaged), `storage`, `download` (the download stopped part way: a network cut, a server error; what was stored is kept, to resume), `load` (the model did not start), `transcribe`. The app says each in plain words (`app/src/domain/voice-flow.ts`, `voice.error.*` in `app/src/i18n/`); the voice screen says an installation failure as one of five (`installFailureOf`, `voicePack.error.*`): the voice is not available from this server or without the Internet (`unavailable`, and `download` with nothing stored), the files received are damaged and nothing is kept (`invalid` with nothing stored), one file received was damaged and dropped while the files before it are kept (`invalid` with files stored: only the damaged file is deleted), the download stopped with part of the voice kept, or not enough space. "Reprendre l'installation" is named only in the two messages where part of the voice is kept, the button that is then shown. None asks her to report it to the health post: each says to type the name meanwhile. Transcriptions run one at a time, in order; a load or a transcription that gets no answer within 180 seconds (`DEFAULT_REQUEST_TIMEOUT_MS`, `timeoutMs` option) is given up, and the worker is terminated and replaced by a new one, which loads the model again for the next request. `cancel()` gives up the transcriptions asked so far (the cancel button, typing, leaving the screen): one that runs stops with its worker, so it no longer uses the battery, and one still waiting for the model is dropped; the model load itself is never cancelled, the next recording needs it. After a worker crash, the next call starts a new worker.
- Why 180 seconds: one 3.3-second utterance took 123 s on one thread with the CPU slowed 6 times, the stand-in for an entry-level phone (Timings below). Whisper always encodes a 30-second window, so an 8-second sentence costs about the same as a name; 180 s leaves about half as much again for a slower phone or a first load, and a worker that hangs (out of memory, a stuck runtime) is still let go of. The person can cancel at any time before that.
- The worker loads a pack once: a second load of the same pack answers at once; another pack replaces the model in memory. Before it creates the pipeline, it checks that the ONNX Runtime files of the pack are in the voice cache (`checkRuntimeInstalled`): when one is missing, Transformers.js would leave ONNX Runtime to import and fetch it from its URL, over the network, so it is refused as `unavailable` instead.
- Threads: ONNX Runtime uses half the cores, at most four, only when the page is cross-origin isolated (`threadCount`), and one thread otherwise, without a warning. On a phone with 2 GB of memory or less (`navigator.deviceMemory`), at most two: each thread is a worker with its own copy of the runtime's JavaScript and stack, next to a model of several hundred megabytes.
- Memory: the app frees the model (terminates its worker) 3 minutes after its last use (`VOICE_IDLE_MS`), and at once when the page is hidden; a recording under way stops when the page is hidden (the microphone closes), a transcription under way finishes first. Three minutes covers the next product of a visit (a check adds several, a minute or two apart; loading again takes seconds on a laptop, more on a phone) and gives the memory back soon after.
- `installVoicePack` streams every file into the Cache API cache that Transformers.js reads (`transformers-cache`, fetched with `cache: 'no-store'` so it is not also kept in the HTTP cache), with progress, cancel and resume (files already stored are kept), checks the free storage first and asks for persistent storage; `isVoicePackInstalled` checks every file; `removeVoicePack` deletes them. `voicePackInfo` reads `voice-pack.json`, and uses the installed copy when offline or when the server answers with something else than JSON; with no installed copy, an answer that is not JSON (a host that serves the app page for every address) reads as `unavailable`, never as damaged files.
- The microphone (`createRecorder`) records one channel in an audio worklet, keeps the samples in memory only, stops by itself after 8 seconds (`MAX_RECORDING_MS`) and releases the microphone at once. Each start owns its own microphone stream: a start cancelled during the permission prompt and answered late closes only its own stream. `resampleTo16k` brings the audio to 16 kHz with a low-pass filter. The samples are transferred to the worker (the page keeps no copy) and dropped after transcription. Audio is never stored or sent, and nothing is ever played back.
- Decoding stops after 96 new tokens, enough for a name or a short sentence.
- The service worker never precaches `voice/` and never answers a `voice/` request with the app page (`app/vite.config.ts` and `app/src/pwa/sw-setup.ts`, tested in `app/src/pwa/workbox.test.ts` and `sw-setup.test.ts`).
- Cross-origin isolation: the app's service worker (`app/src/sw.ts`, vite-plugin-pwa `injectManifest`) adds `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` to every answer of its precache, so a page it serves is cross-origin isolated and ONNX Runtime may use threads. The first visit and a hard reload are served by the network without these headers and run on one thread; the next start is isolated. Everything the app loads is from its own origin (fonts, the knowledge pack, the referral file, the voice pack, the speech worker), so nothing else changes. The speech worker's script (`assets/worker-*.js`: Transformers.js and the JavaScript of ONNX Runtime, about 490 KB) is not in the app precache: the service worker keeps it in a cache of its own (`siapso-voice-worker`) once a voice is installed: after the installation, and again when a model is loaded, the page asks the worker in control of it to keep the very script it runs (the speech worker says its address when it starts), and a worker waiting with an update, if any, to keep its own, so an update waiting (or one that failed) never leaves the page without its script offline; every install of a new version of the app that finds a voice installed caches the new script first and fails otherwise (so an update never leaves an installed voice without its worker offline), older scripts go when the new version activates, and the cache goes with the last voice. Its answers, cached or from the network, carry the isolation headers (a worker script under COEP needs them). `app/e2e/voice.spec.ts` starts the real worker from that cache after a new install, offline and isolated, and checks that nothing is requested from `voice/`; `app/e2e/isolation.spec.ts` checks the isolation, the fonts, the pack, the referral file and the screens under it, and the offline and update tests run on the same worker.

## Commands

- `pnpm voice:convert`: build the packs into `speech/convert/out/` (`speech/convert/README.md`).
- `pnpm voice:install-local`: copy them, with the ONNX Runtime files and the licence texts, to `app/public/voice/` for local preview and phone tests (`docs/testing.md`).
- `pnpm eval:speech`: word error rate of the packs on FLEURS and on consented volunteer recordings, with Transformers.js in Node; protocol, consent forms and committed results in `eval/speech/`. Baseline of 2026-11-04 (100 sentences per language): Wolof pack 54.1 % on `wo_sn`, French pack 30.3 % on `fr_fr`. Name accuracy is pending recordings.
- Conversion tool versions (hashed lock `speech/convert/requirements.txt`, moved to patched versions on 2026-11-05, alerts in `docs/dependencies.md`): torch 2.10.0 (CPU build), onnx 1.22.0, onnxruntime 1.23.2, transformers 4.57.6, optimum 2.1.0, optimum-onnx 0.1.0, filelock 4.2.1 (Python 3.11 and 3.12; 4.1.0 on 3.10). After the move, the French pack was converted again and the 20-sentence FLEURS check gave the same 30.0 % (534 words) as before.
- `pnpm voice:bench`: the timing bench below (`BENCH_PORT`, default 4180; `BENCH_OUT` writes the JSON report).

## Timings

Measured with `pnpm voice:bench` on 2026-11-04 on a laptop (Windows 11, 12 logical cores, headless Chromium 156 from Playwright 1.64.1): Wolof pack, the 3.3-second FLEURS utterance of `speech/bench/fixtures/`, offline (no request at all after going offline, and none ever outside the bench origin). Headless Chromium had no WebGPU adapter, so the model ran on WebAssembly. Without cross-origin isolation ONNX Runtime uses one thread; since SCRUM-31 the app's service worker isolates every page it serves (Runtime above).

| Measure                                                            | One thread | Cross-origin isolated (several threads) |
| ------------------------------------------------------------------ | ---------- | --------------------------------------- |
| Model load from the Cache API, in the worker                       | 2.9 s      | 2.6 s                                   |
| Transcription in the worker, first                                 | 13.8 s     | 7.3 s                                   |
| Transcription in the worker, median of 3                           | 13.1 s     | 6.7 s                                   |
| Same pipeline on the page thread, median of 3, no throttling       | 13.2 s     | 6.5 s                                   |
| Page thread, CPU throttling 4x (stand-in for a mid-range phone)    | 73.8 s     | not measured                            |
| Page thread, CPU throttling 6x (stand-in for an entry-level phone) | 122.7 s    | not measured                            |

- Chrome DevTools CPU throttling does not reach workers (the worker at 4x took 14.1 s, as without throttling), so the throttled runs use the same pipeline and settings on the page thread. With threads, ONNX Runtime computes in workers, so throttling means nothing there.
- Whisper always encodes a 30-second window: a short name costs almost as much as a long sentence. The encoder dominates.
- Runs vary on one machine: an earlier run gave a 16.8-second median in the worker.
- Transcription of the fixture: "gërpidamil bi ci giza doom moo taxaw ba tey" (reference: "great pyramid bi ci giza dong mo taxaw batay").
- What this means: on one thread, the stand-in for an entry-level phone needs about two minutes per utterance, which is not usable. Several threads halve the time on the laptop. The ways forward are cross-origin isolation for the app (done in SCRUM-31: the service worker adds the COOP and COEP headers), and a lighter Wolof model (SCRUM-42).

### What the team must measure on real phones

Throttling only approximates a phone. Before the voice screen ships, measure on at least one entry-level Android phone (about 2 GB of memory) and one mid-range phone, in Chrome:

1. transcription time for a 2-second name and an 8-second sentence, Wolof and French packs, with and without cross-origin isolation;
2. model load time and memory (a 2 GB phone may close the tab): in remote DevTools, the memory of the tab with the model loaded, with one thread, two threads (what a 2 GB phone gets) and four; whether Chrome closes the tab or other apps while the model is loaded; whether 3 minutes of keeping the model (`VOICE_IDLE_MS`) is too long on such a phone, and the time to load it again after it was freed;
3. download time on the health post wifi and on mobile data, storage used, whether persistent storage is granted, and whether the pack is still there after a week;
4. whether WebGPU is offered, and whether it is faster with these 8-bit graphs;
5. battery and heat over ten transcriptions;
6. accuracy with real voices and background noise (SCRUM-32);
7. in the app: that `crossOriginIsolated` is true once the app was opened twice (remote DevTools console), the time from "Terminer l'enregistrement" to "J'ai entendu", the recording through the phone's own microphone, how the microphone permission is asked and how it is allowed again after a refusal (the steps of `voice.deniedBrowser1` to `3` in Chrome, and of `voice.deniedApp1` to `3` in the installed app, which has no browser menu), and whether the installed app (added to the home screen) keeps the voice pack.

To run the bench page on a phone: `pnpm --filter @siapso/speech exec vite build --config bench/vite.config.ts`, then `pnpm --filter @siapso/speech exec vite preview --config bench/vite.config.ts`, forward port 4180 over USB (`docs/testing.md`) and call `siapsoBench` from the remote DevTools console.

## Lighter model (SCRUM-42)

Goal: under 100 MB and usable on an entry-level phone. Measured on 2026-11-05 (`eval/speech/results/2026-11-05-4bit-summary.md`): 4-bit weights (MatMulNBits, block 32, embedding kept in int8) take the Wolof model files from 298.7 MB to 207.8 MB and the FLEURS word error rate from 54.1 % to 57.1 %; the French base pack goes from 110.2 MB to 83.0 MB and from 30.3 % to 32.1 % (100 sentences each, Node). Quantisation alone does not reach 100 MB for Whisper small, and 4-bit weights were not faster (Node, and a WebAssembly run of the encoder): they cut download and memory, not compute. The way to under 100 MB is a smaller model (Whisper base 4-bit is 83 MB), which must be fine-tuned for Wolof: that needs a GPU and consented data, so `speech/train/` holds the plan (`README.md`: data, licences, CNERS opinion, consent), the script (`finetune.py`, not run) and the options with sizes (`distill.md`).

Browser support: Transformers.js 4.3.1 has the `q4` data type, and the ONNX Runtime Web build it pins contains the `MatMulNBits` operator and ran the 4-bit encoder and a decoder step in WebAssembly in Node (`speech/eval/wasm-q4-check.mjs`, output `eval/speech/results/2026-11-05-wasm-q4-check.json`; the encoder took 3.1 s against 2.1 s in 8-bit, one run on synthetic input, indicative only). A committed test (`speech/test/wasm-matmulnbits.test.ts`) checks that the pinned WebAssembly binaries contain `MatMulNBits` and run a 4-bit fixture correctly. Not tested in a browser or on a phone, and the app's worker and the pack manifest only know `q8` today.

## Voice input in the app (SCRUM-31)

- The search screen has a large microphone button beside the field, shown only where the browser can record and run the model (a secure page, `getUserMedia`, Web Audio with an audio worklet, module workers, the Cache API); the keyboard path is whole without it.
- Without an installed voice, the button opens the voice screen (`#/voice`, also linked from the settings): what the voice does, that the voice stays on the phone, the question "Dans quelle langue allez-vous dire les noms ?" with the two languages and their size (Wolof first, offered in plain sight), and no language chosen for her (live test round 2: a French preselection was installed by a Wolof speaker who tapped the big button); the question says that changing the language later means removing this voice and downloading the other one. The install button reads "Installer la voix" until she answers, and asks for a language if pressed before; then the model of the language chosen, the advice to install once on wifi at the health post with its size, and "Installer la voix en ...". Only that button downloads: it reads `voice-pack.json`, then installs with a progress bar and a cancel. Offline, the button is off (`aria-disabled`, still focusable) and described by "Connectez-vous à Internet pour installer la voix."; a tap downloads nothing. An installation cut short keeps its files; the screen says how much is on the phone (`storedVoicePackBytes`), takes its language as the one chosen, and offers to go on or to remove them. Installed: how to use it, and a removal asked twice. One voice at a time, to spare the phone's storage: to change the language, remove the voice first, then download the other. Whether a voice is installed is read from the Cache API only (`installedVoicePackInfo`), never from the network; `app/e2e/voice.spec.ts` checks that no `voice/` file is requested before the install button, nor offline.
- With a voice installed: a tap records (the elapsed seconds, a ring that pulses around the button and stays still under reduced motion, a cancel button); a second tap finishes, or it ends by itself at 8 seconds. The model loads while she speaks. "Je réfléchis..." while it transcribes, then "J'ai entendu : ..." and the text goes in the search field as if typed: the candidates are the resolver's, exactly as for a typed name, and each is confirmed on its confirm screen. Nothing is added from the voice. While it records, the screen says which language the voice understands ("J'écoute en wolof."). A text the voice heard with candidates on offer is not added as typed: she chooses a candidate, or types the name first, and after Back from a confirm screen "Je ne trouve pas ce produit" stays away (the history entry keeps that the text was heard). When no candidate matches, the screen says so and offers to type the name or to choose it from the whole list, and "Je ne trouve pas ce produit" is offered at once, through the "Ce nom ressemble à :" question as for a typed name (live test round 2: a woman who uses the voice because typing is hard could not add an unknown syrup). When the voice heard no name at all, one message: "Je n'ai pas entendu de nom. Réessayez, ou écrivez le nom." with "Écrire le nom", never "nothing matches". A name the voice heard is labelled "Vous avez dit" (never "Vous avez écrit") on the confirm screen, the check list and the result (`said` in the check state), and the confirm screen keeps the name on the box a candidate was found by ("Nom sur la boîte : Brufen"). The letters typed before the microphone are kept on the search entry, so the way back from the voice screen finds them. The whole list (every remedy, or every medicine family once, by first letter) has a filter field and a row of letters that jump to their heading, lists the names on the boxes of the generics as entries of their own ("Cytotec", under C, "Nom sur la boîte de Misoprostol (générique)"), and says each local name as the search does: a Wolof name is "Nom local", a French or English one "Autre nom". A refused microphone is explained in short numbered steps that fit where the app runs: in Chrome, the three dots, site settings, microphone; in the installed app (display mode `standalone` or `fullscreen`, `app/src/voice/display-mode.ts`), which has no browser menu, the phone's settings, the app by its name, permissions, microphone; then the field takes the focus on "Écrire le nom". A model that does not start, or files damaged on the phone, say to remove the voice and install it again if it happens again, with a button to the voice screen. The flow is a pure state machine (`app/src/domain/voice-flow.ts`: idle, opening, recording, transcribing, heard with candidates, heard without candidate, error, refused, cancelled).
- The app builds the worker as an ES module (`worker: { format: 'es' }`) and resolves ONNX Runtime Web with the `onnxruntime-web-use-extern-wasm` condition, so no 25 MB wasm file lands in the app. The small `@siapso/speech` chunk (about 12 KB) is precached and counts in the app budget; the worker chunk (about 490 KB) is cached with the voice (above) and counts with it: `pnpm budget:app` says its size apart. Both load only when the voice is used.
- The licences of the voice software, models and data, with the full Apache 2.0 and MIT texts, are on the licences screen (`#/licences`, from About).

## Known limits

- Each pack carries its own copy of the ONNX Runtime binaries (26.9 MB): installing both packs stores them twice.
- A page the service worker did not serve (the first visit, a hard reload) is not cross-origin isolated: ONNX Runtime then runs on one thread (see the timings).
- The model stays in memory for 3 minutes after its last use, so a second name is quick; on a 2 GB phone this may still matter (measure it).
- WebGPU is not measured (no adapter in headless Chromium). The 8-bit graphs may run partly on the CPU under WebGPU: measure before relying on it.
- ONNX Runtime Web is the build that Transformers.js 4.3.1 pins (`1.31.0-dev.20260914-8d85527a0`).
- Safari before version 26 without WebGPU is not tested.
- A new version of a pack at the same URL is not detected: files already in the cache are kept by path, and their sha256 is not checked on the phone (hashing 200 MB would need the whole file in memory). Remove the pack, then install it again; versioned and signed packs come with SCRUM-38. "Damaged" files are therefore found by their size only: a file of the right size with other bytes is not detected.
- Strengths said in words are read in French only ("mille", "quatre cents", "un gramme", `resolver/src/number-words.ts`); Wolof number words are not read yet.
- The 180-second time limit comes from a laptop with the CPU slowed 6 times, not from a phone: measure a first load and a transcription on an entry-level phone, and change `DEFAULT_REQUEST_TIMEOUT_MS` if needed.
- When a recording stops, its last incomplete audio worklet block (under 2048 samples, 43 ms at 48 kHz) is dropped.
