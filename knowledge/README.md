# Knowledge pack: how to write a rule

Rules, messages and danger signs are YAML files read by `tools/knowledge` (`@siapso/pack-tools`). The tool refuses a malformed or unsafe rule, then builds the pack the app and the engine use. Medicines, classes and plants live in `registry/`.

Content files are licensed CC-BY-4.0: every YAML file starts with `# SPDX-License-Identifier: CC-BY-4.0`. Keys are kebab-case; the build maps them to the engine's camelCase.

## Layout

| Path                                  | Content                                                                    |
| ------------------------------------- | -------------------------------------------------------------------------- |
| `knowledge/pack.yaml`                 | `version`, `date`, `clinically-validated`, optional `minimum-safe-version` |
| `knowledge/sources.yaml`              | the sources policy: allowed, fact-only and forbidden sources               |
| `knowledge/rules/<id>.yaml`           | one rule per file, file name equals `id`                                   |
| `knowledge/messages/<id>.yaml`        | one message per file (French and English), file name equals id             |
| `knowledge/danger-signs.yaml`         | list of danger signs                                                       |
| `registry/substances.yaml`            | list of substances                                                         |
| `registry/classes.yaml`               | list of substance classes                                                  |
| `registry/products/<id>.yaml`         | one medicine per file, written by hand                                     |
| `registry/products/bdpm.yaml`         | list of medicines generated by the BDPM import (see below)                 |
| `registry/plants/<id>.yaml`           | one traditional remedy per file                                            |
| `knowledge/schema`, `registry/schema` | JSON Schemas (editors can use them for completion)                         |

## Add a rule

1. Create `knowledge/rules/<id>.yaml` with a kebab-case `id` equal to the file name.
2. Fill the fields:
   - `kind`: `pregnancy`, `breastfeeding`, `interaction`, `herb-drug`, `toxicity`, `duplicate`, `max-dose`, `condition`, `contraception-info` or `reminder`.
   - `when`: `subject` (`{ substance: x }`, `{ class: x }` or `{ plant: x }`, required except for `reminder`), and optionally `requires` (any-of list of `{ with: <subject> }`, `{ condition: <id> }` or `{ sign: <danger sign id> }`, a danger sign present now), `unless-conditions`, `unless-with` (a list of subjects: the rule does not apply when any item matches one of them), `pregnancy-windows` (`lt12`, `12-19`, `20-29`, `30-plus`), `breastfeeding` (`baby-age-weeks-max`, `premature`), `max-mg-per-day` (kind `max-dose` only: applies above it) or `from-mg-per-day` (kind `max-dose` only, instead: applies from it, the amount included; a danger rule held at before the next dose when only a box of unknown strength may reach it, the case of `possible-message` below), `strength-above-mg` (substance subject only, and not on `max-dose` or `duplicate` rules, where it would drop items from the sum or the count).
   - `level`: `unknown`, `next-contact`, `before-next-dose` or `danger`.
   - `evidence`: `A` to `E`, or `0` (quoted, see below).
   - `danger-rationale`: required when `level: danger`, forbidden otherwise.
   - `message`: the id of a file in `knowledge/messages/`; `possible-message` (kind `max-dose` only, optional): the message of an excess that depends on the box (reached only with the highest strength of a family), said before the next dose; `max-dose-may-exceed` when absent.
   - `sources`: each with `source`, `locator`, `accessed` (and optionally `url`, `quote`).
   - `review`: `status` (`draft` or `validated`) and `reviewers`, and `reviewed-on` once validated.
3. Create the matching `knowledge/messages/<id>.yaml` with `fact` and `risk` in `fr` and `en` (optional `risk-detail`, `orientation`, and `orientation-accompanied`, the orientation said in accompanied mode, only beside an orientation).

```yaml
# SPDX-License-Identifier: CC-BY-4.0
id: nsaid-pregnancy-from-20-weeks
kind: pregnancy
when:
  subject: { class: nsaid }
  pregnancy-windows: [20-29, 30-plus]
level: before-next-dose
evidence: A
message: nsaid-pregnancy-from-20-weeks
sources:
  - source: openfda
    locator: 'Ibuprofen tablets, drug label, section 8.1 Pregnancy'
    accessed: 2026-11-04
review:
  status: draft
  reviewers: []
```

## Evidence scale

The evidence level says what kind of proof backs the rule. It sets how the message is worded (the French wording is the model for the message text).

| Evidence | Meaning                                         | Message wording (French)                                                   |
| -------- | ----------------------------------------------- | -------------------------------------------------------------------------- |
| A        | Clinical effect demonstrated in humans          | "peut provoquer ..."                                                       |
| B        | Human pharmacokinetics, often outside pregnancy | "une étude chez des volontaires a montré ..."                              |
| C        | Case reports or observational study             | "des cas ont été rapportés ..." or "des études ont observé ..."            |
| D        | Animal or laboratory study                      | "des tests en laboratoire suggèrent ... ce n'est pas prouvé chez la femme" |
| E        | Theoretical                                     | "c'est possible, mais cela n'a pas été étudié"                             |
| 0        | No data                                         | "pas d'information fiable"                                                 |

Evidence `D`, `E` and `0` cannot give a level above `next-contact`, except for rules of kind `toxicity`. The checks reject such a rule instead of capping it silently.

In YAML, quote the evidence level `0` (`evidence: '0'`): unquoted, it is a number and the check refuses it.

Set `review.reviewed-on` (a date such as `2026-11-04`) when a reviewer validates the rule.

## Medicines from the BDPM

`registry/products/bdpm.yaml` is generated, never edited by hand. Download `CIS_bdpm.txt` and `CIS_COMPO_bdpm.txt` from the official BDPM download page (https://base-donnees-publique.medicaments.gouv.fr/telechargement) into a folder outside the repository, then run:

```sh
pnpm knowledge:import-bdpm <folder>
```

The import (`tools/knowledge/src/import-bdpm.ts`) reads the files as Windows-1252 and keeps the marketed medicines ("Commercialisée") taken by mouth, on the skin or rectally whose active substances all map, through the table `SUBSTANCE_LABELS`, to substances of `registry/substances.yaml` (isotretinoin and metronidazole by mouth only). It takes the strength in mg of one unit (tablet, capsule, sachet, suppository) and the brand from the first words of the denomination. The selection is deterministic: sorted by first substance id then denomination, one product per denomination. Every marketed product of the brands most used in Senegal (`PRIORITY_BRANDS`: Doliprane, Efferalgan, Dafalgan, Codoliprane, Advil, Nurofen, Voltarène, Aspégic, Kardégic, Flagyl, Bactrim, Néo-Codion, Ixprim, Contramal, Dépakine, Coumadine, Doxy, Vibramycine, Tardyferon B9, Dermoval, Fervex, Clamoxyl, Rifadine, Tégrétol) is always kept; the other products fill the rest, at most 3 per brand, 15 per substance (priority products included) and 315 in total (`MAX_ENTRIES`), the total being taken rank by rank across substances. The total was 300 until fluconazole and methotrexate joined the registry (2026-11-05): their products take their rank in the cut, and 315 keeps every product the 300 cap kept before. The 15 products that came in are the 9 fluconazole and 5 methotrexate products and ZESTRIL 20 mg (lisinopril), the next product in rank, which no rule reads differently from the other lisinopril products. Each product carries `source: { bdpm: <CIS code> }`. The other names people use for a brand (`LOCAL_NAMES`: "Doliprane codéine" for CODOLIPRANE) are given to every product of the brand as French local names, `checked: false`. The import prints the size in bytes and the sha256 of each input file: record them, with the download date, in the `bdpm` entry of `knowledge/sources.yaml`, so that anyone can check that the same files give the same `bdpm.yaml`.

A product file holds one product named after the file, or, for a generated file, a list of products named by their own ids.

## Authoring metadata

The product `source` (BDPM code or `demo-manual`) and the plant `parts` are validated, but they are authoring metadata and are not carried in the runtime pack.

## Message rules

- `fact` and `risk` are required in French and English; `risk` and `orientation` contain no digit (numbers go in `fact` or `risk-detail`).
- No message ever gives a dose: in `fact` and `risk-detail`, a number followed by a dose unit or frequency (mg, g, ml, µg, mcg, UI, IU, milligramme, milligram, millilitre, milliliter, gramme, gram, comprimé, tablet, gélule, capsule, cuillère, spoon, sachet, goutte, drop, prise, dose, "par jour", "fois par jour", "per day", "times a day", "times per day", "times daily") is refused. Dose thresholds live only in the rule (`max-mg-per-day`, `strength-above-mg`) and in its source quotes.
- No dose in words either, in any field, read on the plain text (lowercase, without accents, one straight apostrophe, single spaces): "une seule prise", "une unique prise", "un seul comprimé", "a single dose"; a single dose with "unique" after an article, "en" or "à" ("une prise unique", "une dose unique", "un comprimé unique", "en prise unique", "à dose unique"); a number in words before a unit ("deux comprimés", "douze gouttes", "trente gouttes", "twelve tablets", "forty tablets"), number words joined by a space, a hyphen, "et" or "and" being one number ("vingt et une gouttes", "quatre-vingt-dix gouttes", "twenty-five drops", "one hundred and twenty drops"); an article before a unit that is always an amount ("un comprimé", "une gélule", "une cuillerée", "une goutte", "une fois par jour", "une fois par semaine", "a tablet", "a teaspoon", "a drop"); "once a day", "twice daily", "two times daily", "three times per day", "trois fois par semaine", "once a week", "three times a week"; a dose at bedtime ("le soir au coucher", "au coucher", "at bedtime"); half a unit ("un demi-comprimé", "half a tablet"); the time between doses, "toutes les" or "every" then a number of hours in words or digits ("toutes les six heures", "toutes les quatre à six heures", "every 6 hours"); a drink measured in cups, glasses or bowls (tasse, verre, bol, cup, glass, bowl, mug) after a number in words or an article ("deux tasses par jour", "une tasse de tisane par jour", "un verre", "a cup of tea"), but not a dish the remedy is mixed into ("un bol de sauce", "a bowl of soup"); the times of day ("matin et soir", "le matin et le soir", "morning and evening"), except in a sentence that describes a study (étude, essai, volontaires, study, trial, volunteers: "des volontaires en prenaient matin et soir"). Units include cachet, pilule, pill, suppositoire, gramme, milligramme and millilitre. Not refused: "une dose" or "une prise" alone ("à une dose plus forte"), "même pris une seule fois", "even taken once", which is how a warning is written; a duration ("pendant six heures", "for six hours"); "a drop in" a measured quantity, after an optional the, her, his or their (blood, pressure, heart, sugar, glucose, level, rate, count, temperature, weight, milk), which is a fall ("a drop in blood pressure"; "a drop in each eye" is refused); an article then "sachet de", "sachet d'" or "sachet of" and a powder or granules ("un sachet de poudre", "a sachet of granules"), which is a form ("un seul sachet" and "deux sachets de poudre" are refused); "a drop in" an amount, a volume, a number or the fluid ("a drop in the amount of fluid around the baby"); "une pilule contraceptive" or "une pilule du lendemain", a method; "prises de sang", blood tests ("deux prises de sang"). The one exception: the message of a reminder (a message only reminder rules use) may give the number of doses of a preventive schedule, in the form "au moins trois doses de SP" / "at least three doses of SP", and nothing else.
- The orientation of the message of a rule, of a danger sign or of the built-in `danger-sign` message never gives more time than its level, read as whole words whatever the apostrophe or the space: a danger says now ("maintenant", "immédiatement", "now", "immediately") and never "aujourd'hui", "rapidement", "dès que possible", "today", "soon" or the next dose; neither level says the coming days, the next visit or contact, tomorrow, a week, an appointment, a consultation or later. At the before-the-next-dose level only, a consultation, a "rendez-vous" or an appointment followed within two words by that level's own deadline ("avant la prochaine prise", "before the next dose") is not later: "Montrez-le en consultation prénatale avant la prochaine prise" is accepted, "Montrez-le à la consultation" is not, and any other later word in the orientation still counts. A danger has no such deadline: a consultation is refused whatever follows. A long-term treatment at the before-the-next-dose level says "rapidement" ("soon"), as below. The check refuses a later timing and a danger that does not say now.
- Never write a word that implies safety, verification or an order to change a treatment (the check lists them), no em dash and no emoji.
- Write for both modes: an orientation or a risk speaks of "the treatment", "this product" or "the woman", never of "your treatment" or "what you take", because in accompanied mode the reader is not the patient. Reminders (accompanied mode only) speak of the woman ("elle").
- An orientation that names different people or a different timing than the interface's accompanied default (before the next dose: "Montrez ce produit à la sage-femme ou à l'infirmier avant qu'elle en reprenne."), or that speaks to her ("ne changez rien"), has an `orientation-accompanied`, said in accompanied mode instead (a profile or a passer-by at a depot), so that the cards of one result name the same people and timing in each mode (live test round 2, SCRUM-52). The check refuses it without an orientation, and refuses in it "vous", "votre", "vos", "you" and "your", and "la prochaine visite" or "the next visit": it says "à sa prochaine visite" / "at her next visit", her visit and never another's. It is checked as an orientation (no digit, wording, timing of its level).
- No orientation points to "cet écran" / "this screen": nothing is kept for a passer-by, so the screen is gone once the next one starts. The grey messages say "Montrez ce produit à la sage-femme ou au pharmacien à la prochaine visite." ("Montrez ce produit à la sage-femme ou à l'infirmier à sa prochaine visite." in accompanied mode), the words of the interface default of the unknown level, so two grey cards never name different people.
- Every grey message names its subject ("ce produit", the remedy), because woman mode hides the fact: a risk never starts with a bare "Cela ne veut pas dire".
- The messages `nothing-found`, `nothing-applies`, `not-recognised`, `danger-sign`, `max-dose-not-computable` (the note given when units per day are entered for a product of unknown strength whose family gives no strength), `max-dose-may-exceed` (the finding of a daily maximum exceeded only with the highest strength of the family of a box of unknown strength) and `evidence-0` must exist. Both dose messages say "avant la prochaine prise" (the timing check reads them at the before-the-next-dose level). A product that no rule of the pack giving findings reads (as its subject, whatever the strength threshold, or as a partner; a reminder or a contraception note does not count, since it says nothing about the product's risk) gets `nothing-found`; a product that such a rule reads, when no rule applies to the situation (another term, not pregnant, no partner), gets `nothing-applies`. Since the live test round 2 (SCRUM-52) both say the same words, one grey wording for a product the app has recognised ("Rien n'a été trouvé sur ce produit", said just after the app found it, read as "the app does not know this medicine"): "Notre base ne contient rien sur ce produit pour cette situation", a gap in the base, never an all-clear, then "Notre base ne dit pas si ce produit peut faire du mal dans cette situation", and who to show it to and when. The result reads their fact then their risk, with no version inside the sentence: the version and date of the base are said near the top and at the end of the result.
- Say an unknown positively, and only as far as it is true: "Notre base ne dit pas si ce produit peut faire du mal dans cette situation" / "Our knowledge base does not say whether this product can cause harm in this situation" when only the base is silent (`nothing-found`, `nothing-applies`), and "On ne sait pas si ce produit peut faire du mal" / "We do not know whether this product can cause harm" when nobody has reliable information (`not-recognised`, `evidence-0`, the default of the unknown level); never "ne veut pas dire qu'il est sans risque" / "does not mean it is risk-free". The check allows "sans risque" inside that negation, but a listener who hears only the end of a sentence read aloud would hear "sans risque". The app wording test (`app/src/result-wording.test.ts`) refuses both phrases on the result of every reference case.
- Say who to show and when in the orientation, the line both modes read, and never in a field the result keeps behind "Pourquoi ?" (the `risk-detail` of every message, and the `fact` of a message of a rule that gives findings or of a remedy; the fact of `nothing-found`, `nothing-applies`, `not-recognised` and of a danger sign is read in both modes). The check refuses there a French imperative ("dites-le", "allez", "montrez", "parlez-en", "prévenez", "signalez", "surveillez", "retournez", "ne le donnez pas", "n'attendez pas", "ne changez rien"), an obligation ("il faut", "elle doit aller", "le médecin doit être vu") and "à montrer"; "dites" and "faites" only at the start of a clause or with a pronoun, since "les crèmes dites éclaircissantes" and "des études faites chez l'animal" are not orders. In English it refuses an imperative at the start of a sentence or after a colon or a comma ("tell the midwife", "if she bleeds, go to the health post", "do not give", "watch the baby"), "never give", and "should", "please" or "make sure" anywhere; "Never studied" or "Keep" at the start of a sentence state a fact, and the English check reads a text without its quotations between double quotes, since a quoted title names a source ("Medicines in pregnancy. Never give up on the data", "Keep, watch and wait"). What a label or a test says is not one ("la notice ne la recommande pas", "only a test can tell"): write what a label asks without "should" ("the label allows it only when absolutely necessary"). A conditional "go now" in the orientation of a lower level is accepted (castor oil late in pregnancy: "Après une césarienne ou une autre opération de l'utérus, allez au poste de santé maintenant."), and the result offers "Voir qui appeler" under it.

## Thresholds the clinical committee must confirm

- `paracetamol-max-daily` uses 3000 mg per day: the DOLIPRANE 1000 mg and EFFERALGAN 1000 mg RCP dosage tables give 3 g per day as the maximum daily dose for adults and children from 50 kg, and allow up to 4 g per day only on medical advice. The same labels keep 3 g as the maximum for adults under 50 kg, chronic malnutrition or dehydration.
- `paracetamol-overdose` uses from 6000 mg per day, twice the maximum of `paracetamol-max-daily` (6 g included): an engineering default for "a clearly toxic daily amount" (live test round 2, SCRUM-52), kept by the clinical review of the pull request as more cautious than 8 g.
- `registry/substances.yaml` gives paracetamol `adult-min-strength-mg: 400`, the lowest adult form of the registry: the certain daily amount of a box of unknown strength leaves out the lower strengths of its family (children's powders).
- `aspirin-analgesic-dose-pregnancy`, `aspirin-analgesic-dose-pregnancy-before-20-weeks` and `aspirin-renal-failure` flag aspirin above 100 mg per unit, the French label limit for low-dose aspirin (the label applies the rules of doses above 500 mg per day to doses between 100 and 500 mg).

Rules about a long-term or vital treatment (valproate, carbamazepine, warfarin, blood pressure medicines, the malaria and HIV treatments, SP with cotrimoxazole, prescribed aspirin, a strong skin cortisone used for a long time) give their own orientation, so that "before the next dose" is never read as "skip a dose": talk to the midwife or the doctor soon, changing nothing in the treatment meanwhile. An epilepsy treatment says plainly that it must not be stopped without a doctor. Short, non-vital courses (cyclines, painkillers) keep the default orientation of their level.

## Situations of the profile

The profile asks about long-term situations (`hiv-cotrimoxazole`, `tuberculosis-treatment`, `epilepsy-treatment`, `uterine-scar`, `renal-failure`, `hepatic-failure`, `sickle-cell`). A rule reads a situation through `requires: [{ condition: ... }]` or `unless-conditions`. The result screen says, in both modes and before the cards, in clear, every ticked situation that no rule of the pack reads: the base does not take it into account yet, and a medicine taken for that treatment or illness is looked at only if it is on the list (it never tells to add a medicine that may already be there). Today `tuberculosis-treatment`, `epilepsy-treatment` and `sickle-cell` are read by no rule. `hiv-cotrimoxazole` is always read (`sp-with-cotrimoxazole`, `amodiaquine-with-antiretrovirals`, `iptp-reminder`), so the screen never says it: a test of the app (`app/src/domain/result-view.test.ts`) fails if the pack ever stops reading it, and the section would then be shown at a tap only again (`docs/privacy.md`).

## Questions for the clinical committee

The pack is a test pack, not clinically validated (`clinically-validated: false`, every rule `draft`). The live test round 1 (SCRUM-49) changed the content below; each change is a point for the clinical committee (a pharmacist and a midwife, see `GOVERNANCE.md`) before any field use.

1. `misoprostol-pregnancy-uterine-scar` (new, danger, evidence C, windows from 12 weeks): misoprostol with a uterine scar is now at the same level as castor oil at term with a scar. Sources: Cytotec US label (boxed warning, labor and delivery), GYMISO RCP 4.4. Confirm the level, the danger rationale and the windows (the French label calls rupture very rare in the first trimester).
2. `misoprostol-late-pregnancy` (new, danger, evidence C, 30 weeks and more, not with a scar): confirm the level and whether it should start at 20 weeks, since the label says the risk rises with the term.
3. NSAIDs from 24 weeks (`nsaid-pregnancy-from-20-weeks`, unchanged level before-next-dose): the French label contraindicates any intake from 24 weeks, even once, because of a risk of fetal death. The danger level is reserved for an immediate vital risk with a written rationale, and the term windows have no 24-week boundary, so the level was not raised. Decide whether NSAIDs, and aspirin above 100 mg, from 24 weeks should be red, which needs a new window.
4. `tetracyclines-pregnancy-first-trimester` (new, next-contact, evidence E): the French label prefers, as a precaution, to avoid tetracyclines in the first trimester (no effect shown in animals or in the few human data). Confirm the level and the evidence grade.
5. `aspirin-analgesic-dose-pregnancy-before-20-weeks` (new, next-contact, evidence C): aspirin above 100 mg per unit before 20 weeks, as the other NSAIDs (ASPEGIC 500 mg RCP 4.6). Confirm the threshold and the level.
6. `carbamazepine-pregnancy` (new, before-next-dose, evidence A, as valproate): TEGRETOL RCP 4.6 and the Tegretol US label. The message says that an epilepsy treatment must not be stopped without a doctor; confirm the wording and the grade (population data). The `valproate-pregnancy` message now says the same.
7. `paracetamol-hepatic-failure` (new, condition, before-next-dose, evidence B) and `nsaid-renal-failure` (new, condition, before-next-dose, evidence A): the profile does not say how severe the failure is, so the rules take the level of the contraindication in severe failure (DOLIPRANE 1000 mg and ADVIL 200 mg RCP). Decide whether a lower paracetamol daily maximum (2 g in mild to moderate liver failure) should become a max-dose rule, and whether paracetamol with kidney failure, NSAIDs with liver failure and aspirin with kidney failure need rules.
8. Situations read by no rule (tuberculosis treatment, epilepsy treatment, sickle cell): the result now says so in a note. Decide which rules these situations need (for example rifampicin interactions, antiepileptic interactions, hydroxyurea or sickle-cell crises).
9. `tramadol-breastfeeding` (raised to before-next-dose in SCRUM-52, question R-5): the message no longer says that the French label accepts a single dose, and a check now refuses any dose in words. The live test asked for at least before-next-dose for the mother of a newborn, like codeine (both are in the FDA recommendation of 2017): decide whether the level should depend on the baby's age.
10. Wording: fever during pregnancy, castor oil and misoprostol at the danger level now say "Allez au poste de santé maintenant" (go now), as the danger signs screen; baby danger signs in the codeine and tramadol messages say "maintenant"; clobetasol in pregnancy and bitter kola with quinine say "Parlez-en rapidement ... sans rien changer en attendant" instead of "dans les prochains jours"; the clobetasol messages no longer say that a short use "is possible" or "can be considered"; grey messages say who to show and when ("à la prochaine visite") and name their subject; the paracetamol daily maximum tells the woman that her amount seems too high; messages speak of "the treatment" rather than "your treatment"; the IPTp reminder speaks of the woman. Confirm the urgency of each and the national wording (danger signs list of Senegal).
11. Evidence label C now reads "des cas ont été rapportés ou observés" (it said "des cas graves", which overstated the metronidazole and clay messages). Confirm the wording of the evidence scale.

## Danger signs

`knowledge/danger-signs.yaml` is one fixed list for everyone, in three groups: pregnancy (fever, vaginal bleeding, convulsions, severe headache with blurred vision, the baby moving less or no longer moving, very strong abdominal pain, waters breaking before labour, fast or difficult breathing, swollen face or hands), after the birth (heavy bleeding, fever, convulsions, severe headache with blurred vision, fast or difficult breathing, very strong abdominal pain, painful or swollen calf or chest pain) and the baby (not feeding, very sleepy and hard to wake, fast or difficult breathing, convulsions, fever or feeling cold). Each sign cites the WHO guide it comes from (facts only, the labels are our own words) and, for the baby, a peer-reviewed study. Fever during pregnancy has its own message (`danger-sign-fever`: it can be malaria, go to the health post now for a test); the other signs use `danger-sign`. Every danger sign says now, as the danger signs screen does.

The list is not clinically validated: the clinical committee must align it with the national list of danger signs of Senegal before any field use.

## Levels policy

`danger` (red) is reserved for danger signs and for rules with a written `danger-rationale` explaining the immediate risk. Today six rules use it: castor oil at term with a uterine scar, misoprostol with a uterine scar, misoprostol late in pregnancy, paracetamol from twice the daily maximum, and codeine or tramadol while breastfeeding with a baby danger sign ticked now. A danger rule is held at before the next dose when its window is still ahead (reached only through the term look-ahead) or when only a box of unknown strength may reach its amount: a danger is said "now" only when it is certain now. The interface names a danger that comes from a product rule "Danger : à montrer maintenant", never "Signe de danger", on the result and on who to call. There is no safe level: `unknown` means we have no reliable information.

## Sources policy and NOTICE

`knowledge/sources.yaml` lists the sources the content may rely on:

- `allowed`: may support a rule (LactMed, openFDA labels, FDA Drug Safety Communications, BDPM, the ANSM interactions thesaurus, peer-reviewed literature).
- `fact-only`: may support a fact or a danger sign, but their text is never copied, and a rule always also cites an allowed source (WHO documents).
- `forbidden`: never cited, copied, linked or named. Each entry has a `reason` and the `domains` that are refused.

Each allowed or fact-only entry has `id`, `name`, `publisher`, `licence`, `url`, a `version` or an `accessed` date, and the `notice` line printed in `NOTICE`, all in English, then `documents`, the language its documents are written in (`fr` or `en`), and `fr`, its `name`, `licence` and `version` (required when the entry has a `version`) in French. The pack carries `documents` and `fr` with each source, so the French interface names every source in French and says "documents en anglais" beside a source whose citations keep their English titles (the English interface says "documents in French" beside the BDPM and the ANSM thesaurus). A date in a `version` is written as each language writes dates ("downloaded on 4 November 2026", "téléchargés le 04/11/2026").

A citation `url` opens a page a reader can read on a phone: the BDPM page of the RCP or the leaflet, the PubMed record (`https://pubmed.ncbi.nlm.nih.gov/<PMID>/`), the LactMed Bookshelf page of the record (`https://www.ncbi.nlm.nih.gov/books/NBK<n>/`), the DailyMed page of a US label (`https://dailymed.nlm.nih.gov/dailymed/drugInfo.cfm?setid=<set_id>`), the IRIS handle page of a WHO document (`https://iris.who.int/handle/10665/<n>`), or no link. The check refuses an API answer, a bulk archive, a repository file or a raw record (a host `api.`, `eutils.` or `ftp.`, a path ending in `.json`, `.xml`, `.zip` or `.gz`, a path with `/server/api/` or `/bitstreams/`, `retmode=xml`), which show code or start a download over mobile data. A source entry may name the hosts its citation links must open (`link-hosts`): the openFDA labels are linked on DailyMed only, which `NOTICE` says, with the caveat that DailyMed shows the latest version of a label, not necessarily the effective date cited.

A `locator` names the record in its own words. A BDPM citation gives the product title as the BDPM writes it, the section and the update date, with no English word, so that the French interface cites a French document in French: `ADVIL 200 mg, comprimé enrobé, RCP 4.4 (ANSM, 13/02/2025), CIS 68634000` (or `notice 2` for the package leaflet, whose `url` ends in `typedoc=N`; an RCP's ends in `typedoc=R`). US labels and English articles keep their English titles.

The check refuses:

1. a rule that cites no allowed source;
2. a rule that cites only fact-only sources;
3. a reference to a forbidden source id, a URL under a forbidden domain (subdomains included, in any string of `knowledge/`, `registry/` or `eval/`), and a forbidden name in any content file or comment, whatever the case or accents (only `knowledge/sources.yaml` may name them, in its `forbidden` list);
4. a cited source id that `sources.yaml` does not declare.

Plants may cite allowed or fact-only sources. Every danger sign must cite at least one allowed or fact-only source.

Any file in `knowledge/`, `registry/` or `eval/` that the tool does not expect (a stray YAML file, a nested folder, a `.txt` file) is reported as a problem, so that nothing escapes the checks. Under `eval/`, YAML files are parsed; `.md` and `.json` files (and the `README.md` of `knowledge/` and `registry/`) are scanned as text for forbidden names and URLs; audio files (`.wav`, `.flac`, `.ogg`, `.opus`, `.webm`, `.mp3`) are accepted without a scan.

The root `NOTICE` file is generated by `pnpm knowledge:build` from the sources actually cited (no date of generation). `pnpm knowledge:check` fails when the committed `NOTICE` differs from the generated one: run the build and commit the result. The pack's `sources.json` lists the same sources.

## Run the checks

```sh
pnpm knowledge:check   # prints one problem per line as "file: path: message", exit code 1 if any
pnpm knowledge:build   # writes app/public/pack/ (fragments, pack.json, manifest.json) and NOTICE
```

The build empties `app/public/pack/` first (it only cleans a directory named `pack`). It is deterministic (arrays sorted by id, except the danger signs, which keep the order written in `danger-signs.yaml`, the order the screens list them; no timestamp) and fails if the gzipped fragments exceed 3 MB.

The build does not sign the pack: a maintainer makes a release with `pnpm release:build --key <file>`, which builds the pack, signs it (`manifest.sig`) and builds the app. Raise `version` in `pack.yaml` for every published pack, whatever changed, since the app only takes a strictly higher version. To withdraw earlier packs, set `minimum-safe-version` (at most `version`) to the first version that is safe again: it is signed with the manifest, and the app never rolls back below it. Once set it never decreases and is never removed: `pnpm knowledge:check` compares it with `origin/main`. See `docs/pack-signing.md`.
