## [Unreleased]

### Added

- Repository foundation: README, MIT licence, contributing guide, code of conduct, security policy, product context (`PRODUCT.md`).
- Text hygiene check (`tools/hygiene/hygiene.py`): no em dash, no emoji, no AI attribution, Conventional Commits subjects. Enforced by a Claude Code hook, git hooks and CI.
- Developer Certificate of Origin check on pull requests.
- Dependabot version updates for GitHub Actions; Dependabot alerts and security updates enabled.
- impeccable design plugin for interface work.
- `tools/github/merge-pr.sh`: squash-merges a pull request only once every check is green.
- pnpm workspace with engine, resolver, speech and app packages; CI for lint, types, tests, build and end-to-end tests.
- Deterministic evaluation engine (`@siapso/engine`): checks C1 to C12 with the evidence cap, term windows and helpers, pack validation (`parsePack`), forbidden wording check, and guarantee tests over generated contexts.
- Knowledge pack tooling (`@siapso/pack-tools`, `siapso-pack`): JSON Schemas, validation (ids, references, evidence cap, message wording), deterministic build with manifest and size budget; content skeleton with the builtin messages.
- Sources policy (`knowledge/sources.yaml`) and provenance check in `siapso-pack`: every rule cites an allowed source, fact-only sources never stand alone, forbidden sources cannot be cited, named or linked, and every cited source must be declared. The pack carries the cited sources.
- `NOTICE` generated by `siapso-pack build` from the sources actually cited; `siapso-pack check` fails when it is out of date.
- Engine: `strengthAboveMg` rule condition and per-sign danger messages.
- Visual system (`DESIGN.md`): design tokens with tested contrast (reading text at 7:1 for sunlight) and a never-green check, self-hosted Atkinson Hyperlegible Next (OFL), base components (`Button`, `TextField`, `LevelIcon`, `LevelBadge`, `ResultCard`, `DangerBanner`) with a distinct pictogram per level and a hatched unknown level, and a development-only gallery at `#/design`.
- Starter clinical content (not clinically validated): 24 rules on medicines and traditional remedies in pregnancy and breastfeeding, the IPTp reminder and three contraception notes, each citing allowed sources with verbatim quotes; 21 danger signs with their sources and a fever message; messages in French and English.
- Starter registry: 55 substances, the `nsaid`, `tetracycline`, `raas-blocker` and `valproate` classes, 14 traditional remedies, demo products written by hand and 300 medicines imported from the BDPM (brands most used in Senegal always kept).
- `pnpm knowledge:import-bdpm <dir>`: imports medicines from the official BDPM files into `registry/products/bdpm.yaml`; a product file may hold a generated list of products.
- Blocking reference cases (`eval/cases`, schema `eval/schema/case.schema.json`): the 14 cases of the dossier (17 files with the term variants of case 1), each with the exact expected level, findings, reminders and notes. Any change in the engine output for them fails the tests; message ids and wording are checked in both languages.
- Installable offline app shell: a service worker (vite-plugin-pwa, update prompt, never a silent reload) precaches the app, its fonts and the knowledge pack; the pack is checked against its manifest (sha256), validated and kept in IndexedDB; welcome screen (language, then mode) with settings stored in IndexedDB; Home; header with the danger signs shortcut and an offline badge; danger signs route; typed French and English dictionaries; neutral notebook icons and the `Carnet` default name (`VITE_APP_NAME`).
- `pnpm budget:app`: the app stays at or under 1.5 MB without the pack and the voice files, checked in CI.
- `docs/testing.md`: automated checks and how to test in airplane mode on a real phone.

### Fixed

- `setup-repo.sh` now reads the auto-merge setting back instead of trusting the API response.
