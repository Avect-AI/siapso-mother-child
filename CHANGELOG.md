## [Unreleased]

### Added

- Licensing and governance: `REUSE.toml` (REUSE 3.3) with the SPDX texts in `LICENSES/` (MIT, CC-BY-4.0, OFL-1.1, Apache-2.0), `reuse lint` in CI (pinned in `tools/reuse/requirements.txt`), `MEDICAL_DISCLAIMER.md`, `TRADEMARKS.md`, `GOVERNANCE.md` (clinical double review by a pharmacist and a midwife, rule withdrawal within 24 hours, public change log), `THIRD_PARTY_NOTICES.md`, `docs/dpg-mapping.md` (Digital Public Goods Standard) and `docs/intended-use.md`, the shared intended-use paragraph checked by a test.
- Repository foundation: README, MIT licence, contributing guide, code of conduct, security policy, product context (`PRODUCT.md`).
- Text hygiene check (`tools/hygiene/hygiene.py`): no em dash, no emoji, no AI attribution, Conventional Commits subjects. Enforced by a Claude Code hook, git hooks and CI.
- Developer Certificate of Origin check on pull requests.
- Dependabot version updates for GitHub Actions; Dependabot alerts and security updates enabled.
- impeccable design plugin for interface work.
- `tools/github/merge-pr.sh`: squash-merges a pull request only once every check is green.
- pnpm workspace with engine, resolver, speech and app packages; CI for lint, types, tests, build and end-to-end tests.
- Deterministic evaluation engine (`@siapso/engine`): checks C1 to C12 with the evidence cap, term windows and helpers, pack validation (`parsePack`), forbidden wording check, and guarantee tests over generated contexts.
- Knowledge pack tooling (`@siapso/pack-tools`, `siapso-pack`): JSON Schemas, validation (ids, references, evidence cap, message wording), deterministic build with manifest and size budget; content skeleton with the builtin messages.
- Sources policy (`knowledge/sources.yaml`) and provenance check in `siapso-pack`: every rule cites an allowed source, fact-only sources never stand alone, forbidden sources cannot be cited, named or linked, and every cited source must be declared. The pack carries the cited sources.
- `NOTICE` generated by `siapso-pack build` from the sources actually cited; `siapso-pack check` fails when it is out of date.
- Engine: `strengthAboveMg` rule condition and per-sign danger messages.
- Visual system (`DESIGN.md`): design tokens with tested contrast (reading text at 7:1 for sunlight) and a never-green check, self-hosted Atkinson Hyperlegible Next (OFL), base components (`Button`, `TextField`, `LevelIcon`, `LevelBadge`, `ResultCard`, `DangerBanner`) with a distinct pictogram per level and a hatched unknown level, and a development-only gallery at `#/design`.
- Starter clinical content (not clinically validated): 24 rules on medicines and traditional remedies in pregnancy and breastfeeding, the IPTp reminder and three contraception notes, each citing allowed sources with verbatim quotes; 21 danger signs with their sources and a fever message; messages in French and English.
- Starter registry: 55 substances, the `nsaid`, `tetracycline`, `raas-blocker` and `valproate` classes, 14 traditional remedies, demo products written by hand and 300 medicines imported from the BDPM (brands most used in Senegal always kept).
- `pnpm knowledge:import-bdpm <dir>`: imports medicines from the official BDPM files into `registry/products/bdpm.yaml`; a product file may hold a generated list of products.
- Blocking reference cases (`eval/cases`, schema `eval/schema/case.schema.json`): the 14 cases of the dossier (17 files with the term variants of case 1), each with the exact expected level, findings, reminders and notes. Any change in the engine output for them fails the tests; message ids and wording are checked in both languages.
- Installable offline app shell: a service worker (vite-plugin-pwa, update prompt, never a silent reload) precaches the app, its fonts and the knowledge pack; the pack is checked against its manifest (sha256), validated and kept in IndexedDB; welcome screen (language, then mode) with settings stored in IndexedDB; Home; header with the danger signs shortcut and an offline badge; danger signs route; typed French and English dictionaries; neutral notebook icons and the `Carnet` default name (`VITE_APP_NAME`).
- `pnpm budget:app`: the app stays at or under 1.5 MB without the pack and the voice files, checked in CI.
- `docs/testing.md`: automated checks and how to test in airplane mode on a real phone.
- Profile screen (`#/profile`, `#/profile/new`): pseudonym (a nickname, no phone number or address), pregnancy with the term from the last period date, weeks of amenorrhoea, months or "je ne sais pas", read back in words; breastfeeding with the baby's birth date or age (read back in weeks) and prematurity; long-term situations (three more in accompanied mode) with an explicit "none of these"; "no" to both pregnancy and breastfeeding is refused. Profiles are kept in IndexedDB; Home opens her profile in woman mode, a new one in accompanied mode, and names the profile just saved. `contextFromProfile` builds the engine context from a profile and a check; a stored term or age that no longer holds becomes unknown, never a lower level. A term or a baby's age given in weeks or months moves on with the weeks since it was given, and saving the profile again leaves it as stored. A month of pregnancy covers both readings (the month in progress and the months completed). Choice group components (`RadioGroup`, `CheckboxGroup`); text fields keep to the column with a native date input at large text.

- Local name resolver (`@siapso/resolver`): normalisation with French and Wolof spelling variants, trigram and Damerau-Levenshtein scoring, ranked candidates with brand, generic, plant and INN priorities; it never returns a level. `pnpm eval:resolver` runs the evaluation set `eval/resolver/queries.yaml` (top-1 and top-3 accuracy per query type, p95 latency) and fails below `eval/resolver/baseline.json`; CI runs it.

- Review follow-ups: `Note.kind` (`contraception` or `dose`) and a separate `Reminder` type; no `max-dose-not-computable` note when the same rule already triggered C7; `unlessWith` only on `reminder` and `contraception-info` rules (engine and authoring check); resolver stop-words `médicament` and `emplâtre`, age words kept apart (no weight, they pick the variant), prefix inside a multi-word name from 4 characters; `docs/dependencies.md`.
- Engine: the `unlessWith` rule condition (a rule does not apply when an item matches one of its subjects) and the `max-dose-not-computable` note, given when units per day are entered for a product of unknown strength (never a level).
- Registry: `paracetamol-500-generic` and `paracetamol-1000-generic`, offered as variants of the paracetamol generic, and the common brands Coartem, Fansidar, Brufen, Feldene, Ponstan, Indocid, Roaccutane and Cytotec on their generic products.
- Resolver: stop-words for forms, packaging and age groups, a relative cutoff at 0.8 of the best score, and a minimum score of 0.55; the evaluation gains `noise` queries that must get no candidate.
- `tools/github/merge-pr.test.sh`: the merge gate tested with a fake `gh`, after `shellcheck`, in CI.
- Reference case 15: a co-trimoxazole item without the HIV condition gives no IPTp reminder.
- Engine: `CheckedItem.strengthUnknown` (the strength on the box is not known): the item's component strengths are read as unknown, so a `strengthAboveMg` rule applies, the max-dose sum skips the item and the `max-dose-not-computable` note can apply; a value that is not a boolean is refused.
- Product search and confirmation (`#/check`, `#/search/product`, `#/search/plant`, `#/confirm/<kind>/<id>`): Home's "Regarder un produit" opens the check for the active profile, after the profile screen when there is none. The search proposes at most three candidates from the local name resolver as the user types (Wolof names and misspellings included), each with its substances and strengths and the local name it was found by, and offers the other list when the name is only found there. Nothing is added without confirmation: the confirm screen asks the strength written on the box (a strength the user did not type is never preselected; "je ne sais pas", always offered, keeps the product with its strength unknown; a family whose products differ only by their form gets no strength question) and, for a substance with a daily maximum, the units per day (a whole number from 1 to 24, or blank). "Je ne trouve pas ce produit" adds the text typed as an unrecognised item. A product already listed is never listed twice: the confirm screen names it and changes its units per day instead. "Je ne sais pas" never takes the place of a known strength: when the family is listed with a known strength, the confirm screen asks whether it is the same box (keep that product) or another one (a separate item of unknown strength); a known strength takes the place of a box of the family listed without one. A family whose products differ only by their form is shown by its brand and strengths (CODOLIPRANE 500 mg/30 mg). The check says what was added, updated or removed, and a removal can be undone. A minimal result route shows the overall level until the full result screen arrives.
- Result screen (`#/result`): the danger banner first when a finding is a danger (the level, then as its largest line the orientation the danger cards share, or "Allez au poste de santé maintenant." when they differ, announced to screen readers apart from its "Voir qui appeler" action), a summary when there are several findings, then one card per item set and check (the level and orientation of the highest, every distinct risk of the others, so two pregnancy rules on one ibuprofen give one card that says both risks) with the level and its pictogram, the product as confirmed (several products each on their own line), the risk, the term note when the term is estimated or unknown, and who to show and when as the clearest line of the card. Woman mode stops there (a danger sign with a message of its own, such as fever, says its fact first; the note that a daily total cannot be computed is included); accompanied mode adds, after who to show and when, the fact, the detailed risk, the evidence level with its wording, the sources (name and record, a link when there is one, never the quoted text) and the rule, the reminders and the contraception notes. "Nothing found" gives the knowledge base version and date. Every result ends with "Ne changez rien à votre traitement sans en parler à un professionnel.", the knowledge base version and date, "Contenu non validé cliniquement" while the pack is not validated, and "Cet outil ne remplace pas un soignant."; "Revenir à la liste" keeps the check. While the pack or the profile loads the screen says so, and when either cannot be read or the check cannot be evaluated it says so with the way back. Each evaluation is kept in a local history (the last 20 per profile, never sent). A test reads every result string of every reference case in both modes and both languages for forbidden words, numbers in woman mode and the level name.
- `ResultCard` and `DangerBanner` take their heading level from the page outline; the card renders who to show and when itself, at title size, before the source lines.
- Danger signs and the referral circuit (`#/danger`, `#/danger/call`, `#/contacts`): the danger signs screen, one tap from every screen, gives the orientation with its condition, a direct "Voir qui appeler", then the 21 signs in three groups (during pregnancy, after the birth, the baby) as large answers; "C'est grave maintenant" never refuses and shows "Allez au poste de santé maintenant." (the result's own instruction when the circuit is opened from a result), the signs ticked to say when calling, then who to call: each contact with its role, name and number as text and a large "Appeler" `tel:` link, or "Aucun contact enregistré sur ce téléphone." with, in accompanied mode, a way to add one, then the national circuit text of the deployment. The result's danger banner leads there with the same instruction. Contacts are entered on the phone in accompanied mode (role, optional name, number of 6 to 15 digits with spaces and a leading plus) and kept in IndexedDB; a deployment can add `app/public/config/referral.json` (git-ignored, precached for offline use; `referral.example.json` holds roles with empty names and numbers). The app never sends anything, and a test checks that no interface string, in either language, says a message was sent, that someone knows or is coming, or that care has started.
- Danger signs now in the check (`#/signs`): between "Voir le résultat" and the result, "Avez-vous un de ces signes maintenant ?" ("A-t-elle..." in accompanied mode) with "Aucun de ces signes" first and explicit, then the signs of the profile's groups, every group one tap away; an answer is required, and the signs chosen reach the evaluation (a fever now is a danger card).
- Offline voice runtime (`@siapso/speech`, `docs/voice.md`): two optional voice packs converted from open Whisper models, Wolof (`M9and2M/whisper-small-wolof`, MIT) and French (`openai/whisper-base`, MIT, because the Wolof fine-tune lost too much French), quantised to 8 bits by a reproducible script (`pnpm voice:convert`, pinned model revisions, Python requirements pinned and hashed for Windows, Linux and macOS, `speech/convert/lock.py`) and checked on FLEURS (`speech/convert/quick_check.py`). Transformers.js 4.3.1 runs the model in a Web Worker, from the Cache API only: nothing is downloaded without the user's consent (a pack that is not installed is an error, never a download), no request leaves the pack, never the Hugging Face hub or a CDN. The pack is installed on request with progress, cancel and resume, and removed on request; errors carry a reason for the voice screen (`VoicePackError`), transcriptions run one at a time with a time limit. Licence texts of the model chain and the bundled libraries ship in each pack. Microphone capture in an audio worklet, mono, resampled to 16 kHz, kept in memory only and stopped after 8 seconds. The model only proposes text. The service worker never precaches `/voice/`. `pnpm voice:install-local` and `pnpm voice:bench` (offline timing with CPU throttling, not in CI).
- Voice evaluation (`eval/speech/`, `pnpm eval:speech`): word error rate per language and pack with Transformers.js in Node on the voice packs' own ONNX graphs and decoding, a FLEURS baseline (100 sentences per language, results committed in `eval/speech/results/`), a manifest and JSON Schema for consented volunteer recordings (empty for now, so product name accuracy is marked "pending recordings"), the recording protocol, and consent form templates in French and English.
- Speech model card (`speech/MODEL_CARD.md`, Hugging Face format) and licence record (`speech/LICENSES.md`): origin, conversion, measured results with dataset revision, limitations, privacy, per-source licence status of the Wolof training data (two verified CC-BY-4.0, WAXAL CC-BY-SA-4.0 with open questions, ALFFA unverified), and publication steps for the team (not executed).

### Changed

- The `danger-sign` message speaks of one sign ("Ce signe peut mettre la vie..."), as each danger sign gets its own card.
- Knowledge: the orientation for castor oil at term with a uterine scar says "Montrez ce que vous prenez à la sage-femme aujourd'hui", which fits one product or several; rule and danger sign locators hold the record or document title only, their remarks are YAML comments.
- Confirm: a known strength chosen while its family is listed with the strength unknown asks "Est-ce la même boîte que ... ?" first; the same box becomes the known strength in the list ("..., dosage non connu, devient ... dans la liste."), another box is listed apart. A family whose products have no strength in mg (DERMOVAL cream and gel) is named by its brand alone, never by one product she did not choose.
- Result: a danger card whose orientation is the danger banner's instruction leaves it to the banner, so it is said once; in accompanied mode each risk of a card is paired with its own detailed risk, evidence level and capped note.
- The knowledge pack keeps the danger signs in the order written in `knowledge/danger-signs.yaml` (fever and bleeding first), the order the screens list them; other arrays stay sorted by id. Choice answers use the snug line height; the danger banner's instruction never breaks inside a word at large text.
- Speech conversion lock (`speech/convert/`): torch 2.8.0 to 2.10.0, onnx 1.19.1 to 1.22.0 and filelock 4.1.0 to 4.2.1 (Python 3.11 and 3.12; Python 3.10 keeps 4.1.0, which has no patched version), closing the open Dependabot alerts of these three packages; cutoff for new pins moved to 2026-10-22. `docs/dependencies.md` lists the alerts and the exceptions. Supersedes Dependabot pull request 28.

### Fixed

- `setup-repo.sh` now reads the auto-merge setting back instead of trusting the API response.
- The IPTp reminder is no longer shown when co-trimoxazole is entered as a medicine without the HIV condition.
- `merge-pr.sh` merges only when the four required checks are reported and passed; a skipped required check blocks the merge, except the Developer Certificate of Origin check of a Dependabot pull request.
- `pnpm eval:resolver` fails on an empty query file, an invalid baseline or a measure that is not a number.
- `parsePack` refuses an empty component list, a pack date not written `YYYY-MM-DD` and a cited source missing from the pack.
- Reference cases compare the message id of rule findings; the app loader and the pack build share one fragment list (tested); CI runs `pnpm knowledge:check` and fails when the build changes a committed file.
- The BDPM input files are identified by size and sha256 in `knowledge/sources.yaml`, and the import prints them.
- The history of a visit keeps a second evaluation of the same items when its level or rules changed (a corrected profile).
- The test that no card merges two findings with different orientations now evaluates every product and plant of the registry against the rules, whatever their subjects, and names the products and rules of a clash.
