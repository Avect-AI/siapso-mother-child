# Distillation and other ways to a lighter model

Goal: a Wolof and a French pack under 100 MB (today 325.6 MB and 137 MB with the runtime) that answer in seconds on an entry-level phone. Nothing here was trained. Each size says whether it is measured (a file this repository produced) or estimated (arithmetic from measured file sizes and parameter counts). Each accuracy statement is either measured on FLEURS or marked as unknown: no accuracy figure for a trained light model exists.

## Measured starting points

All with 4-bit weights (`speech/convert/quantize_q4.py`: MatMulNBits, block 32, symmetric, round to nearest) and the embedding in int8, as the 8-bit packs.

| Model                                 | Parameters (OpenAI Whisper README) | 8-bit pack | 4-bit pack | FLEURS word error rate, 100 sentences                            |
| ------------------------------------- | ---------------------------------- | ---------- | ---------- | ---------------------------------------------------------------- |
| Whisper small, Wolof fine-tune        | 244 M                              | 298.7 MB   | 207.8 MB   | 54.1 % (8-bit), 57.1 % (4-bit)                                   |
| Whisper base, French (not fine-tuned) | 74 M                               | 110.2 MB   | 83.0 MB    | 30.3 % (8-bit), 32.1 % (4-bit), same 100 FLEURS French sentences |

Where the bytes are, in the 4-bit Wolof small pack (graph sizes): encoder 66.2 MB, decoder 137.4 MB. In the decoder, the token embedding is 51,865 x 768 in int8 (39.8 MB) and the output projection, the same matrix transposed, is another copy (4-bit: about 25 MB), so 65 MB is vocabulary; the 12 decoder layers hold the remaining 72 MB. In Whisper base (4-bit) the encoder is 18.8 MB and the decoder 59.8 MB, of which about 43 MB is the two vocabulary matrices.

## Suggested order

1. A: fine-tune Whisper base on the cleared data; quantise to 4 bits (about 83 MB). Measure on FLEURS and on volunteer recordings. If base matches the small model on names of medicines, stop here for size.
2. D (vocabulary trimming) and E (single copy of the vocabulary) to get from about 110 MB (with runtime) to under 100 MB with margin, and F for speed.
3. Only if base is clearly worse than small: B, distilling small into base with filtered pseudo-labels, and measure whether it closes the gap.

## What to measure at each step

Pack size (sum of the files, runtime counted and not counted); FLEURS word error rate on the same 100 sentences with the same decoding; name accuracy (top-1, top-3 after the resolver) on consented recordings; time per phrase on a real entry-level Android phone in Chrome, with the method of `docs/voice.md`. Timings in Node on a laptop do not predict phone speed: in this experiment 4-bit was not faster than 8-bit: slightly slower in Node, and 1.5 times slower for the French base encoder on the WebAssembly build (indicative: one run, synthetic input, `eval/speech/results/2026-11-05-wasm-q4-check.json`). Smaller weights save download and memory, not compute.
